# PENDING — IP Audit & Protection Register
Date: 20 September 2026
Status: internal working document; not legal advice.

## 1. Priority protection map

### TRADE MARK REVIEW — HIGH PRIORITY
Candidate marks:
- PENDING (core product/service brand)
- PENDING logo / integrated tick wordmark
- PENDING Cash Drop
- PENDING Change
- PENDING Travel Change
- PENDING Perks
- PENDING Resolve
- PENDING Work
- Lucky Penny / No Penny Forgotten — secondary campaign marks; assess distinctiveness/use before filing.

Do not file blindly. Run UKIPO identical/similar searches and choose only goods/services genuinely intended within five years.

Likely areas requiring classification advice include downloadable software/apps, SaaS/software services, financial/payment-related services if actually supplied, advertising/affiliate/marketplace services if actually supplied, and business/admin services. Final class wording requires professional/IPO classification review.

### COPYRIGHT — EXISTS AUTOMATICALLY WHERE ORIGINALITY REQUIREMENTS ARE MET
Preserve dated/versioned evidence for:
- source code
- UI copy and original screen designs/artwork
- specifications and documentation
- original marketing materials
- original graphics/logo artwork
- architecture documents

Git history is useful evidence of development chronology, but does not replace clear ownership documentation.

### REGISTERED DESIGN REVIEW
Assess distinctive visual appearance of:
- integrated PENDING wordmark/tick artwork (where design protection is useful alongside trade mark)
- key app screen/UI visual presentations
- Cash Drop / Travel Change interfaces
- distinctive result cards / physical kiosk UI if developed

Protect appearance, not the abstract business idea.

### PATENT ATTORNEY REVIEW — BEFORE FURTHER TECHNICAL PUBLICATION
Do not assume patentability. Flag for professional novelty/technical-contribution assessment:
- kiosk/coin-counting → user identification → destination/pot routing architecture
- multi-provider Cash Drop routing/settlement mechanism
- any novel technical fraud/duplicate-deposit controls
- any novel machine/payment interaction created later

Business rules such as "find money, choose a pot" alone are not treated here as patent assets. Search prior art before filing.

### CONFIDENTIAL / TRADE SECRET — KEEP PRIVATE
- unreleased shadow roadmap
- partner commercial terms and fee/subsidy formulas
- provider-ranking logic
- fraud/abuse detection rules
- security architecture and credentials
- unreleased B2B/API design details where secrecy has commercial value
- future patent-candidate technical detail until reviewed

Use need-to-know access and written confidentiality/IP-assignment terms with contractors, developers and prospective partners where appropriate.

## 2. Public vs proprietary boundary

PUBLIC / TEST-SAFE
- PENDING name and high-level proposition
- public V3.2 tester experience
- high-level "Money Out There" concept
- high-level public feature names once intentionally announced
- marketing statements intentionally released

PROPRIETARY
- shadow source files and unreleased previews
- monetisation architecture
- partner network architecture
- entitlement/payment internals
- detailed Cash Drop / Travel Change routing
- recovery/perks/business engines
- unreleased data schemas and anti-abuse logic

PATENT-REVIEW HOLD
- technical implementation detail connecting coin-counting hardware/kiosks, identity/QR, regulated settlement and destination allocation
- new technical mechanisms developed from that architecture

## 3. Immediate actions
1. Treat the current public GitHub repository as a disclosure risk for unreleased shadow material. Move proprietary shadow development to a private repository/branch/storage arrangement as soon as practical while preserving commit history.
2. Keep the public tester build separate from proprietary R&D.
3. Run UKIPO clearance searches for PENDING and confusingly similar marks before spending on an application.
4. Decide the initial real goods/services scope before selecting trade mark classes.
5. Export/archive dated copies of logo artwork, code and product specifications.
6. Have a UK patent attorney perform a short patentability/prior-art review before publishing additional Cash Drop technical mechanics.
7. Use an NDA + IP assignment/confidentiality clause before sharing unreleased architecture with external developers/partners.
8. Keep an IP register recording asset, creator, creation date, owner, public disclosure date, protection route and filing number/status.

## 4. Ownership checklist
For every contributor/contractor confirm in writing:
- who created the work
- whether copyright/design rights are assigned to the intended PENDING owner/entity
- confidentiality obligations
- right to modify/license/commercialise
- treatment of third-party/open-source assets
- warranties concerning copied material

Maintain:

## 7. Key legal caution
This register identifies protection candidates. It does not establish that any mark is registrable, any design is novel, or any technical feature is patentable. Clearance, ownership and patentability must be verified before relying on a right.
